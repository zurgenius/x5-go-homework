# Занятие 2: типы и управление потоком

Это локальный комплект задач. Автотесты запускаются у вас командой Go. Требуется Go 1.22 или новее.

## Запуск

Откройте эту папку в IDE. В терминале из папки с `go.mod`:

```bash
go test ./...
go test -v ./...
```

Первый запуск должен показать ошибки проверок: в `tasks.go` стоят заглушки. Пакет должен компилироваться. Реализуйте тела функций, сохраняя имена, параметры, возвращаемые типы и тесты.

Функция здесь служит готовой рамкой для алгоритма. В параметре лежат входные данные, `return` отдаёт результат тесту. Подробно функции разберём на следующем уроке. `[]int64` в этих задачах обозначает последовательность целых чисел. Нам достаточно `len`, обращения по индексу и `range`.

## На занятии

1. `Category`: сумма в копейках. Отрицательная: `invalid`. От 0 до 9999: `small`. От 10000 до 49999: `regular`. От 50000: `large`. Используйте `switch` без выражения. Проверка: `go test -run TestCategory -v`.
2. `FizzBuzz`: для положительного числа, кратного 15, верните `FizzBuzz`, иначе для кратного 3: `Fizz`, кратного 5: `Buzz`. Для прочих положительных чисел верните пустую строку `""`, для нуля и отрицательных: `invalid`. Проверка: `go test -run TestFizzBuzz -v`. Пустая строка означает, что при выводе последовательности преподаватель печатает само число. Такое правило позволяет не добавлять преобразование числа в текст.
3. `Sum`: сумма элементов. Для пустой последовательности и `nil` верните 0. Проверка: `go test -run 'TestStatistics/.*/Sum' -v`.

## Дома

Закончите задачи с занятия и реализуйте оставшиеся функции:

- `Min` и `Max`: минимум и максимум. Для пустой последовательности и `nil` верните 0. Это договорённость данной учебной задачи. Для непустого ввода начните с первого элемента, иначе отрицательные числа могут дать неверный максимум.
- `Average`: среднее как `float64`. Для пустого ввода и `nil` верните 0. Пример: `[1, 2]` даёт `1.5`. Преобразуйте числа до деления.
- `RuneCount`: количество кодовых точек Unicode через `range`. `Goшник` даёт 6, `🙂` даёт 1, `e` с отдельным комбинируемым акцентом даёт 2. Количество кодовых точек может отличаться от количества видимых знаков.

В статистике гарантируется, что входные значения и сумма помещаются в `int64`. Реализовывать обнаружение переполнения не требуется. Среднее может иметь обычную погрешность `float64`. Отрицательные числа в статистике допустимы. Ограничение на отрицательные суммы относится к `Category`.

Пустой срез `[]int64{}` и `nil` для наших алгоритмов оба имеют длину 0. Детально их устройство будем изучать позже.

## Готовность и сдача

```bash
gofmt -w tasks.go
go test ./...
```

Ожидается `ok`. Тесты не меняйте (я проверю). Используйте базовые типы, явные преобразования, условия и циклы. Для `Category` и `FizzBuzz` нужен `switch`, для `RuneCount` нужен `range`: прохождение тестов само по себе не проверяет выбор конструкции.

В комплекте 65 проверочных случаев: 11 для FizzBuzz, 40 для статистики, 8 для категорий и 6 для Unicode. Процент: число прошедших случаев / 65 × 100. Родительские тесты и технические события запуска в процент не входят. Если пакет не компилируется, сначала исправьте ошибки компиляции. Вывод без `-v` показывает итог по пакету, а не процент.
